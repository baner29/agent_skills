# ScribeMe

Write technical documentation that explains how a system works, why a team chose a design, or how to complete an operational task. Scribeme gives coding agents document blueprints, Mermaid diagram guidance, and a Python linter for structure and wording.

## Choose a document type

Use Scribeme to create or improve these documents:

| Document | What it covers |
| --- | --- |
| System architecture | Goals, constraints, system boundaries, components, transaction flows, deployment, and risks |
| Architecture Decision Record (ADR) | Context, decision drivers, considered options, the chosen approach, and its trade-offs |
| Operational runbook or guide | Prerequisites, numbered procedures, hazard notices, expected outputs, verification, and rollback |
| Service and interface brief | Service responsibilities, interface contracts, synchronous and asynchronous behavior, and user impact |

The [skill instructions](./SKILL.md) define each workflow. Generated documents use descriptive engineering headings and focus on the system or task.

## Install Scribeme

Use a coding agent that supports Agent Skills. Installation through `npx` requires Node.js and npm; the bundled validator and evaluation runner require Python 3 and use only the standard library.

From your project directory, install the skill:

```bash
npx skills add baner29/agent_skills --skill scribeme
```

For manual installation, copy the complete `scribeme/` directory into your agent’s supported skills folder. Keep `SKILL.md`, `references/`, `scripts/`, and `evals/` together so relative paths resolve.

## Make your first request

Give the agent the document type, audience, relevant source material, and output path. Include known constraints and decisions so it can describe your system without substituting assumptions for facts.

For an architecture document, try:

```text
Use scribeme to document this project's architecture for new engineers.
Explain the system boundaries, components, and main request flow.
Include Mermaid diagrams and identify missing information for me to fill in.
Save the document to documentation/architecture.md.
```

For a decision record, supply the alternatives and decision criteria:

```text
Use scribeme to draft an ADR from the attached design notes.
Compare the options against our stated requirements, explain the trade-offs,
and keep the status Proposed until the team accepts the decision.
Save it to documentation/decisions/001-event-delivery.md.
```

For a runbook, specify the operation and environment:

```text
Use scribeme to write a staging deployment runbook from our deployment scripts.
Include prerequisites, commands, expected outputs, verification, and rollback.
Flag missing steps rather than inventing commands.
Save it to documentation/staging-deployment.md.
```

Scribeme defaults to `documentation/` in the active workspace. An explicit output path overrides that default. Diagrams use Mermaid code blocks; preview them in a Markdown viewer that supports Mermaid.

## Validate a document

From this repository’s root, run the validator against a generated document:

```bash
python3 scribeme/scripts/doc_validator.py documentation/architecture.md --strict
```

For an installed copy, replace `scribeme/scripts/doc_validator.py` with the script’s installed path. If you chose an output folder other than `documentation/`, allow that location explicitly:

```bash
python3 scribeme/scripts/doc_validator.py docs/architecture.md \
  --strict --allow-any-path
```

The validator reports errors, warnings, and document metrics. Strict mode returns exit code `1` for either errors or warnings; a passing run returns `0`. Without `--strict`, warnings don’t fail the run.

Checks cover selected wording patterns, document location, paragraph length, alert formatting, and required sections for detected decision records. Mermaid checks recognize supported diagram types and compare bracket counts. They don’t fully parse or render diagrams.

A passing result doesn’t establish technical accuracy, standards compliance, or who wrote a document. Review commands, interface contracts, metrics, and operational procedures against your system before using them.

## Run the bundled evaluations

Scribeme has its own runner. From this repository’s root, execute:

```bash
python3 scribeme/evals/run_evals.py
```

The runner writes three built-in sample documents to `scribeme/evals/artifacts/`, checks required sections, and runs the validator. It also checks detection of selected disallowed text patterns and a misplaced document. Existing sample artifacts with the same names are overwritten.

These checks exercise fixed samples rather than documents generated by a live agent. The runner reports warnings but fails on missing sections, validation errors, or failed negative checks. Its cases cover architecture documents, decision records, and runbooks; they don’t include a service-brief case.
